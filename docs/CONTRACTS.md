# Fluid Intelligence Engine — Module Contracts (v1)

**This file is the single source of truth.** Every module MUST match these signatures
exactly. Do not invent alternate names, do not change argument order, do not add
required arguments. Extra *internal* helpers are fine but must not be exported unless
listed here.

---

## 0. Global coding rules (NON-NEGOTIABLE)

1. **ES modules only.** Named exports only. **No `export default`.** No dynamic
   `import()`. All relative import specifiers MUST end in `.js`
   (e.g. `import { makeRng } from '../core/rng.js'`).
2. **No build step, no npm dependencies.** Browser-native ESM + vanilla DOM.
   Node 23 is available for tests/sim only (`node --test`, `node sim/simulate.js`).
3. **Determinism.** Never call `Math.random()` or `Date.now()` inside item generation,
   IRT, CAT, or drill-content code. Randomness comes only from an injected `rng`
   object (see `core/rng.js`). Wall-clock time is only allowed in UI/session timing
   code, and there only via `performance.now()` / `Date.now()` at the call site.
4. **No `innerHTML` with untrusted data.** Item SVG is generated by our own code and
   is trusted; it is injected via `innerHTML` in exactly one helper
   (`ui/components.js -> mountSvg`). Everything else uses DOM APIs / textContent.
5. **Pure functions where possible.** Generators take `(rng, spec)` and return a value.
   No module-level mutable state except explicit caches/registries described here.
6. **Every file starts with a 1-3 line block comment** stating its responsibility.
7. Style: 2-space indent, semicolons, single quotes, `const`/`let` (no `var`).
8. Write files ONLY inside the paths assigned to you. Never edit another agent's file.
   If you need something from a module you do not own, code against this contract and
   assume it exists.

## 1. Culture-fairness constraints (HARD REQUIREMENTS)

The product claim is: *a person from any country, any language, any schooling starts
equal.* Therefore:

### 1.1 Forbidden inside ANY item, option, drill stimulus, or wordless demo
- Letters or words of any script (Latin, Cyrillic, CJK, Devanagari, Arabic, ...).
- Digits or numerals of any script; also no tally marks arranged as a numeral system.
- Mathematical/notational symbols: plus, minus, times, divide, equals, less-than,
  greater-than, percent, radical, infinity, sigma, pi, etc.
- Punctuation used semantically (question mark, exclamation mark).
- Arrows, chevrons-as-arrows, check marks, ballot crosses.
- Culturally loaded glyphs: crescent, 5-point star, 6-point star, any cross form,
  swastika-adjacent hooked forms, yin-yang, heart, playing-card suits, musical notes,
  currency marks, traffic signs, flags, hands, faces, animals, clocks, calendars,
  zodiac, religious or national emblems, emoji.
- Reading-order dependence that only works left-to-right (see 1.3).

### 1.2 Allowed shape lexicon (the ONLY primitives; defined in `src/items/shapes.js`)

    circle, ring, ellipse, semicircle, quarterDisc, square, roundedSquare, rectangle,
    triangleUp, triangleDown, triangleRight, triangleLeft, rightTriangle, diamond,
    trapezoid, parallelogram, pentagon, hexagon, octagon, arc, bar, dot, lShape,
    tShape, zShape, uShape, notchedSquare, notchedCircle

An equal-armed plus/cross primitive is FORBIDDEN — do not add one. The canonical
allowed list is exported as `SHAPE_KEYS` from `shapes.js`; an automated audit test
asserts it does not intersect `FORBIDDEN_KEYS`.

Attributes that may vary: `shape`, `size` (4 steps), `fill`
(`empty|solid|hStripe|vStripe|dStripe|dots|half`), `color` (7-value colourblind-safe
set), `rotation` (multiples of 45 degrees), `count` (1..5, always subitizable),
`position` (grid cell), `lineWeight` (3 steps), containment (nesting depth 0..2).

### 1.3 Reasoning-rule constraints

Allowed rule families (perceptual / relational only):

    constancy, progression, distributionOfThree, rotation, reflection, translation,
    overlayUnion, overlayIntersection, overlayDifference, overlayExclusive,
    containment, quantityProgression, sizeOrdering, symmetryCompletion,
    sequenceAlternation, attributeSwap, ruleChaining

Forbidden rules: prime numbers, Fibonacci, arithmetic on digit values, algebraic
manipulation, modular arithmetic beyond simple visual cycling, formal logic notation,
anything requiring taught mathematics, anything requiring vocabulary.

Every matrix rule set MUST be verifiable from **both** rows and columns where the
family supports it, so the item does not depend on a left-to-right reading habit.
Series items MUST carry a geometric direction cue (a track/rail the elements sit on)
rather than an arrow.

### 1.4 UI chrome

The whole app must be *operable with zero reading*. All instructions are delivered as
**wordless animated demonstrations** (`src/ui/demos.js`). Text labels exist only as
optional affordances behind `src/ui/i18n.js` and must never be required to succeed.
Icons are geometric, from `src/ui/icons.js`.

## 4. `src/core/irt.js` — 3-parameter logistic IRT

    export const D              // 1.702
    export const THETA_MIN      // -4
    export const THETA_MAX      // 7
    export function p3pl(theta, item)           // item = {a,b,c} -> P(correct)
    export function info3pl(theta, item)        // Fisher information of one item
    export function testInfo(theta, items)      // sum over items
    export function seFromInfo(info)            // 1/sqrt(info)
    export function maxInfoTheta(item)          // theta where info3pl peaks
    export function bForMaxInfoAt(theta, a, c)  // inverse of the above
    export function logLik(theta, responses)    // responses: [{a,b,c,correct}]
    export function estimateWLE(responses, opts)
    export function estimateEAP(responses, opts)
    export function estimate(responses, opts)   // dispatcher; default method 'wle'
    export function reliability(se)             // 1 - se^2, clamped to [0,1]

Details that MUST be respected:

- `p3pl` = `c + (1 - c) / (1 + Math.exp(-D * a * (theta - b)))`.
- `info3pl` = `D*D * a*a * ((1 - P) / P) * Math.pow((P - c) / (1 - c), 2)`.
- `maxInfoTheta(item)` = `b + (1/(D*a)) * Math.log((1 + Math.sqrt(1 + 8*c)) / 2)`.
- `bForMaxInfoAt(theta,a,c)` = `theta - (1/(D*a)) * Math.log((1 + Math.sqrt(1+8*c))/2)`.
- `estimateWLE` maximises `logLik(theta) + 0.5 * Math.log(testInfo(theta, items))`
  (Warm's weighted likelihood, implemented numerically: coarse grid over
  `THETA_MIN..THETA_MAX` at step 0.05, then two ternary-search refinements to ~1e-4).
  NO analytic derivatives — this avoids sign bugs.
- `estimateEAP` uses grid quadrature with prior `N(opts.priorMean ?? 0,
  opts.priorSd ?? 1.4)`. The deliberately wide prior avoids over-shrinking elite
  scores toward the mean.
- Both return `{ theta, se, method, converged, n }`. `se` for WLE comes from
  `seFromInfo(testInfo(thetaHat, items))`; for EAP it is the posterior SD.
- Zero responses -> `{ theta: 0, se: Infinity, ... }`. All-correct / all-wrong patterns
  must NOT return NaN; they clamp to `THETA_MIN`/`THETA_MAX`.

## 9. The Item object (produced by every generator)

    {
      id: 'matrix:12345:7',          // `${family}:${seed}:${variant}`
      family: 'matrix',
      seed: 12345,
      prompt: { svg: '<svg .../>', width, height },
      options: [{ id: 'o0', svg: '<svg .../>', width, height }, ...],  // 6 or 8
      answerId: 'o3',
      meta: {
        ruleCount: 3,
        ruleTypes: ['progression', 'distributionOfThree', 'rotation'],
        abstractness: 2.4,             // mean RuleDef.abstractness
        elementCount: 9,
        distractorSystematicity: 0.83, // fraction of distractors built by partial rule
                                       // application rather than random perturbation
        wmLoad: 4,                     // 1..6 simultaneous relations to hold
        perceptualSalience: 0.2,       // 0..1, how much a surface heuristic helps
        optionCount: 8,
        generatorVersion: 1
      },
      irt: { a: 1.42, b: 2.10, c: 0.11 }   // filled by calibration.priorIrtParams(meta)
    }

**Hard rules for generators:**

- Exactly one option satisfies the full rule set. Verify programmatically before
  returning; if verification fails, resample (max 50 attempts) then throw.
- All options must be pairwise distinct by canonical key (`cellKey`).
- Distractors: target `distractorSystematicity >= 0.7` — each distractor comes from
  applying a *subset* of the rules correctly and mis-applying one (near-miss), or
  applying a rule to the wrong dimension. Random perturbation is a fallback only.
  This is what makes an item discriminate: partial understanding must land on a
  wrong answer, not on the right one.
- Item SVG must contain no `<text>` elements. An audit test enforces this.

## 10. `src/items/calibration.js`

    export const DIFFICULTY_MODEL   // documented coefficient object
    export function priorIrtParams(meta, family)  // -> {a,b,c}
    export function itemKey(item)                 // family + structural signature (NOT the seed)
    export function updateBank(bank, { key, theta, correct })  // online Bayesian b update
    export function bankSummary(bank)
    export function blendedParams(item, bank)     // prior + posterior -> {a,b,c}

Difficulty model (design-time priors; documented in `docs/PSYCHOMETRICS.md`):

    b = B0
      + B_RULES    * (ruleCount - 1)
      + B_ABSTRACT * (abstractness - 1)
      + B_WM       * (wmLoad - 1)
      + B_ELEMENTS * Math.log2(elementCount / 4)
      - B_SALIENCE * perceptualSalience
      + B_FAMILY[family]

    B0 = -1.10, B_RULES = 0.92, B_ABSTRACT = 0.55, B_WM = 0.38,
    B_ELEMENTS = 0.30, B_SALIENCE = 1.20

    a = A0 + A_SYS * distractorSystematicity - A_SAL * perceptualSalience + A_FAMILY[family]
    A0 = 0.80, A_SYS = 1.10, A_SAL = 0.45        // clamp a to [0.45, 2.60]

    c = 0.85 / optionCount   // slightly below chance: distractors are attractive,
                             // so blind guessing underperforms uniform chance

`B_FAMILY` / `A_FAMILY` are per-family offsets, each within `[-0.5, 0.5]` for b and
`[-0.25, 0.35]` for a, and MUST each carry a one-line rationale comment.

Online update: the b posterior is Normal with prior mean = model b, prior sd = 0.60.
Each observation `(theta, correct)` applies one damped Newton step on the 3PL
log-likelihood with respect to b, damped by `1 / (n + 4)`. Store `{ n, b, sumInfo }`
per `itemKey`.

## 12. `src/core/cat.js` — computerised adaptive test

    export const CAT_DEFAULTS
      // { minItems: 18, maxItems: 40, targetSE: 0.30, optionCount: 8,
      //   cutIndex: 100, ciLevel: 0.90, warmup: 4 }

Session object:

    {

      submit(optionId, rtMs),     // -> { correct, theta, se, index, done }

      get state(),                // { n, theta, se, done, reason, history }

      serialize()
    }

`result()`:

    {
      index, ci: { lo, hi }, theta, se, reliability,
      eliminated,               // boolean
      itemsUsed, medianRtMs,
      byFamily: { matrix: { n, pctCorrect, meanB }, ... },
      byContentGroup: { ... },
      informationCurve: [{ theta, info, se }],   // theta -3..6 step 0.25
      finishedReason: 'precision' | 'maxItems' | 'decisive'
    }

**Elimination gate (per product spec, implemented precisely):**

- A candidate is eliminated iff their final reported index is **below 100**.
- The test does not stop on a *provisional* sub-100 estimate: while `n < maxItems`,
  if the `ciLevel` interval still contains index 100, keep testing. This makes the cut
  accurate rather than merely fast — it is the cut the spec asks for, measured
  properly.
- Warmup: the first `warmup` items target theta ~0.3 to avoid an unstable start; after
  that, `b = bForMaxInfoAt(thetaHat, a, c)`.
- **Randomesque exposure control:** generate 6 candidates at the target difficulty,
  rank by `info3pl(thetaHat, ...)`, pick uniformly among the top 3.
- **Content balance:** no `contentGroup` may exceed 40% of administered items; no
  single `family` may exceed 25%.

`calibration.test.js`, `staircase.test.js`, `items.test.js` (generation validity plus
a culture-fairness audit over 500 sampled items across all families),
`curriculum.test.js`, `store.test.js`.

## 23. Simulation (`sim/simulate.js`)

`node sim/simulate.js` prints a report:

1. **Theta recovery** — 4000 simulated examinees from `N(0,1)` plus an elite
   over-sample at theta 2.5 / 3.5 / 4.5; report bias, RMSE and mean SE by true-theta
   band.
2. **Test information function** across theta -3..6, and the fraction of information
   above theta 2 (index 130) and theta 4 (index 160).
3. **Elite separation** — AUC for classifying theta >= 2 vs theta < 2, and theta >= 4
   vs 2 <= theta < 4.
4. **Item exposure** — distribution of families and administered b values.
5. **Cut accuracy** — false-elimination and false-qualification rates at index 100.

Exit non-zero if RMSE > 0.40 in the core range or the 100-cut error rate > 5%.

## 24. `tools/build-single.mjs`

Bundles the app into ONE self-contained `dist/eq-game.html` for publishing:

- Reads `index.html`, finds the module entry.
- Walks the ESM graph from `src/main.js`, rewriting every relative specifier to a bare
  specifier `app:<normalised-path>`, and emits a `<script type="importmap">` whose
  `imports` map each bare specifier to a
  `data:text/javascript;charset=utf-8,<encodeURIComponent(source)>` URL.
- Inlines CSS into a `<style>` block.
- **Do not** rewrite exports; rewrite only `from '...'` and `import '...'` specifiers.
  This keeps real module semantics and avoids name collisions.
- Prints the output size.

## 25. Entry `index.html` and `src/main.js`

`index.html`: minimal shell, `<div id="app">`, `<script type="module"
src="./src/main.js">`, links the stylesheet, sets `<meta name="viewport">` and
`color-scheme`.

`main.js`: loads the profile, builds the router, mounts, wires the bus, and enforces
the gate — a profile with `status: 'eliminated'` may only reach `#/eliminated` and
`#/about`; a profile with `status: 'new'` is redirected to `#/` and cannot reach
`#/train`.

## 26. `src/core/merge.js` and `src/core/sync.js` — cross-device profiles

`mergeProfiles(a, b) -> profile` is a **join-semilattice**: idempotent, commutative and
associative. Those three properties are what make a repeating sync loop converge instead
of oscillating, and they are asserted as property tests in `test/merge.test.js`, not
assumed. Counters take `max`, never `sum` — summing is not idempotent. `status` and
`currentIndex` are *derived* from the newest assessment in the merged history, never
copied, so elimination cannot be escaped by merging. Per-field rules: `docs/SYNC.md`.

`src/core/sync.js` owns the client half. Local storage stays the source of truth and every
read and write in the app remains synchronous and offline; this module only pushes and
pulls in the background.

- `syncAvailable()` — false on `file://` and in the standalone build, so everything
  downstream becomes a no-op rather than an error.
- `syncEligible()` — `syncAvailable()` and (signed in **or** code-linked).
- `generateCode()` — 20 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (no `O/0`,
  no `I/1/L`) via `crypto.getRandomValues`, with modulo bias removed by resampling.
  Never `Math.random` for a credential.
- `syncNow({ profile })` — resolves `{ ok, profile, reason }` and **never throws**.
- The code travels in an `x-sync-code` header, never a URL.

## 27. Authentication — `api/_auth.js`, `api/auth/*`, `src/core/auth.js`

Sign-in is **recommended, never required**. Nothing about the assessment or the training
changes for a guest, and no route is gated on it. Full design and reasoning: `docs/AUTH.md`.

Server (`api/_auth.js`, zero dependencies, `node:crypto` only):

- `hashPassword` / `verifyPassword` — scrypt `N=16384, r=8, p=1`, 64-byte key, 16-byte
  salt, parameters recorded in the stored string, compared with `timingSafeEqual`. A
  stored key under 32 bytes is **rejected**, because scrypt's shorter output is a prefix
  of its longer one and a truncated row would otherwise still verify.
- `createSession` / `readSession` / `destroySession` — opaque 256-bit tokens stored as
  `sha256(token)`; the cookie is `HttpOnly; SameSite=Lax` and `Secure` behind https.
  `Lax`, not `Strict`: the Google callback is a top-level cross-site redirect.
- `setOAuthState` / `readOAuthState` — HMAC-signed short-lived cookie carrying `state`,
  the PKCE verifier and `next`. Compared in constant time on the way back.
- `sessionSecret()` — returns `null` below 32 characters, and every caller fails closed.

Routes: `GET|DELETE /api/auth/session`, `POST /api/auth/password`,
`GET /api/auth/google` (start **and** callback, so only one redirect URI is registered).
`GET /api/auth/session` also reports which providers are configured, so the UI never
offers a button that cannot work.

`api/profile.js` accepts either identity and **prefers a session over a sync code**;
account profiles live in `user_profiles`, code profiles in `profiles`, same document
shape and the same `mergeProfiles`.

Client (`src/core/auth.js`): no token ever reaches JavaScript — the session is an
`HttpOnly` cookie. `authAvailable()` is false off an http(s) origin. `withPassword` and
`signOut` resolve an outcome object and never throw; a failed sign-in is an ordinary
result, not an exception. `googleUrl(next)` accepts only same-document hash routes, so
the flow can never become an open redirector.

Constraint carried over from §1.4: `#/signin` is the **only** screen exempt from the
labels-off setting, because two unlabelled input boxes are not a fair test of anything.
Every assessment and training surface stays wordless.
